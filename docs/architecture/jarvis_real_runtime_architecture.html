What JARVIS Really Is

Actual core

JARVIS is a Python FastAPI service plus a transport-agnostic pipeline. The CLI, TUI, web UI, GUI, and voice surfaces are wrappers around the same internal service and pipeline objects.

Best no-special-command use

Use direct Python imports: core.pipeline.process_message for assistant requests and core.tools.executor.tool_executor for direct tool execution.

Not magic automation

Many features are present as route/tool/provider adapters, but real operation depends on optional services, API keys, local apps, Ollama models, Docker, browser tooling, email/OAuth credentials, and provider health.

Implementation update: the headless automation roadmap now lives at docs/architecture/HEADLESS_AUTOMATION_ROADMAP.md. The first API slice adds GET /api/tools, GET /api/tools/{name}/schema, and POST /api/tools/execute, backed by the canonical ToolExecutor.

How To Use Features Without JARVIS CLI, TUI, GUI, Or Special Commands

1. Send a normal assistant request directly through the canonical pipeline

import asyncio
from core.pipeline import process_message
from core.pipeline.messages import Request

async def main():
    req = Request(
        text="Summarize this repo and suggest the next build task",
        transport="python",
        user_id="local-user",
        session_id="scratch-1",
        metadata={"context": "No UI, direct Python call"},
    )
    res = await process_message(req)
    print(res.text)
    print(res.metadata)

asyncio.run(main())

2. Execute a tool directly

import asyncio
from core.tools._constants import ToolBlock
from core.tools.executor import tool_executor

async def main():
    block = ToolBlock("web_search", "latest Python packaging recommendations")
    desc, result = await tool_executor.execute(block, session_id="scratch-1", owner="local-user")
    print(desc)
    print(result)

asyncio.run(main())

3. Discover available tools from code

from core.tools.execution.handlers import get_registered_tools

tools = get_registered_tools()
print(len(tools))
for name, kind in sorted(tools.items()):
    print(name, kind)

4. Use the server without Jarvis commands

# Start with standard Python/uvicorn, not jarvis.py:
python -m uvicorn core.main:app --host 127.0.0.1 --port 8000

# Then call standard HTTP endpoints:
POST http://127.0.0.1:8000/api/chat
POST http://127.0.0.1:8000/v1/chat/completions
GET  http://127.0.0.1:8000/api/diagnostics
GET  http://127.0.0.1:8000/mcp/tools

This still uses the FastAPI web service as a transport, but it avoids the Jarvis-specific CLI, TUI, GUI, and web UI wrappers.

Observed Real Limits In This Working Copy

Broken route import

Fixed in the first headless automation slice: core.routes.chat.__init__ now imports the actual router from core.routes.chat.whatsapp_routes, and that router imports its chat handler locally from whatsapp_chat_routes.

Missing automation router

Fixed in the first headless automation slice: automation.routes now exposes /api/automation/status, /api/automation/whatsapp/send, and /api/automation/instagram/send. The status endpoint does not launch Selenium.

Docker sandbox unavailable

Corrected after verification: Docker Desktop is available in the current environment, and core.sandbox.docker_sandbox.docker_sandbox.available reports True. The earlier unavailable message was stale or process-context-specific.

Secret decryption failures

Several stored secrets failed to decrypt during app import, including provider and messaging keys. Integrations depending on those credentials will not work until secrets are repaired or reset.
